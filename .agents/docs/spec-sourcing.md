# CSS Spec Sourcing Context

The live spec source for this fuzzer is the CSS Working Group editor draft index at `https://drafts.csswg.org/`, with the W3C current-work page as a cross-check for completed specifications and drafts.

The generator should keep explicit coverage for modern CSS modules that parser implementations often lag on: CSS Syntax, Selectors 4 and 5, Nesting, Cascade Layers, Conditional Rules, Media Queries, Container Queries, Scope, Values and Units, Color, Pseudo-Elements, Anchor Positioning, Scroll-driven Animations, View Transitions, Animations, Transitions, Paged Media, Counter Styles, Grid, Fonts, Custom Properties, and Houdini-related at-rules such as `@property`.

The spec fetcher stores a machine-readable index and examples under `data/specs/`. Those files are generated artifacts; they should be refreshed deliberately before a major fuzzing campaign.

Default `fetch-specs -- --download` coverage is derived from the live CSSWG index: select the highest level currently listed for each parser-relevant spec family, including CSS modules whose slugs do not start with `css-`, such as `animation-triggers`, `compositing`, `fill-stroke`, and `filter-effects`; add hand-picked current levels that remain important parser targets; skip non-parser-target joke specs such as `css-egg-1`; add the external Houdini Properties and Values API draft; and keep every extracted example from each downloaded spec. The generated `examples.json` records selected specs, downloaded specs, failed downloads, per-spec example counts, and the live index URL. Fetching fails by default when any selected spec cannot be downloaded; use `--allow-fetch-failures` only for debugging a partial corpus. Use `--max-examples-per-spec N` only for deliberately bounded campaigns, and use `--slugs all` for an exhaustive index scrape when campaign runtime matters less than coverage.

Treat API-only CSSWG drafts as out of scope for default CSS parser campaigns unless they contain CSS syntax. For example, keep `web-animations-css-integration`, but do not select the `web-animations-2` API draft by family prefix; its examples are WebIDL and should be rejected by the spec corpus normalizer rather than turned into CSS fuzz seeds.

The generated spec corpus is now an active generator input. `generate` and `fuzz` require the configured corpus path by default, so a missing `data/specs/examples.json` fails loudly instead of silently dropping live spec coverage; old manifest-free corpora, corpora with failed spec downloads, and corpora older than the default 72 hour freshness window are rejected for the same reason. Use `--max-spec-corpus-age-hours N` only when replaying an older campaign intentionally, and use `--no-spec-corpus` only when intentionally testing grammar-shaped and curated seeds alone. The fetcher skips examples embedded in issue blocks, and the loader filters obvious prose, HTML fragments, JavaScript helper snippets, placeholder ellipses, and malformed adjacent declarations before turning spec examples into fuzz seeds. The generator also mutates downloaded examples deterministically by pairing them with generated rules or wrapping nest-safe examples in conditional/group at-rules.

Run `vp run verify-spec-corpus` after refreshing specs and before a campaign. This gate requires the generated `csswg-index.json` next to the corpus, checks both manifest ages against the configured freshness limit, checks that the corpus and index were produced by the same fetch, checks that selected and downloaded specs include the latest level for every live CSSWG spec family in that index, checks that required modern CSS specs are present in the selected and downloaded sets, fails on recorded download failures, fails when any selected spec lacks generated coverage from both normalized examples and curated seeds, and prints selected specs with zero extracted or zero normalized examples as explicit coverage warnings.
